# Skyrim Extraction — независимое ядро 0.1

Первый исполняемый этап проекта: постоянный учёт предметов и рейдов. Skyrim для запуска не нужен.
Это библиотека на JavaScript (ES modules) с SQLite, симуляцией двух игроков и автоматическими тестами.
Сетевой сервер, Skyrim-плагин и игровой адаптер ещё не реализованы. Для разработки выбран SkyMP + SkyrimPlatform;
целевая архитектура описана в [решении о стеке](docs/STACK.md), проверка в игре ещё впереди.

Полный [план разработки до версии 1.0](docs/DEVELOPMENT_PLAN.md): объём релиза, этапы, зависимости, критерии готовности,
оценка в активных агенто-часах и работа, доступная без установленной игры.

## Запуск

Нужен Node.js 24.x с модулем `node:sqlite`. Проверено на Node.js 24.19.0 в Linux.
Проверка на Windows ещё не проводилась; команды не требуют Unix-утилит.

Клонируйте репозиторий или распакуйте архив, откройте терминал в папке `skyrim-extraction` и выполните:

```sh
node --version
npm test
npm run demo
```

`npm install` не нужен: внешних зависимостей нет. Некоторые сборки Node могут выводить предупреждение об экспериментальном SQLite API.
Демонстрация создаёт временную базу и удаляет её после завершения. Для постоянного состояния передайте собственный путь конструктору `ExtractionCore`.

## Что реализовано

- Регистрация игрока и однократная выдача стартового комплекта доверенным кодом.
- Создание рейда и контейнера с предметами из фиксированного каталога.
- Перенос выбранных экземпляров из схрона в рейд. Один активный рейд на игрока.
- Подбор лута после разрешения игрового адаптера.
- Смерть: весь рейдовый инвентарь переносится в логический контейнер; схрон сохраняется.
- Другой участник этого рейда может забрать вещи погибшего.
- Экстракция: все оставшиеся предметы переносятся в схрон одной транзакцией.
- Повтор успешно выполненной команды возвращает сохранённый результат без повторного изменения данных.
- Перезапуск процесса и переподключение читают сохранённое состояние.
- Закрытие рейда удаляет оставшийся лут и снаряжение не эвакуировавшихся игроков.
- По умолчанию подбор и экстракция запрещены, пока адаптер не подтвердит условия.

Каждый экземпляр предмета представлен одной строкой и находится в одном месте.
Серверная модель использует собственный UUID предмета, а не Skyrim FormID.
Расходование зелий, боеприпасы, стеки, зачарования, износ и перенос свойств предметов из Skyrim пока не реализованы.

## Граница доверия

`ExtractionCore` — внутренний сервис. Нельзя публиковать его методы напрямую в HTTP/WebSocket API.
Методы `registerPlayer`, `createRaid`, `recordDeath`, `closeRaid` вызываются только доверенной системой.
В будущем идентификатор игрока поступает из аутентифицированной сессии, а не из тела клиентского запроса.

Адаптер реализует синхронные, не меняющие мир функции:

```js
const authority = {
  canPickup({ playerId, raidId, containerId, itemId }) {
    // Проверить доступность контейнера, расстояние, состояние персонажа по миру сервера.
    return false; // До подключения настоящей проверки.
  },
  canExtract({ playerId, raidId, exitId }) {
    // Проверить существование выхода, позицию, время нахождения в зоне и условия выхода.
    return false;
  }
};
```

Ядро принимает только буквальное `true`; Promise не является разрешением.
В `demo.mjs` и тестах проверки намеренно разрешают операции: это симуляция, не античит.
Бой, смерть и позиции сами по себе этим ядром не проверяются.
Контейнер после смерти пока запись в базе: игровой объект в Skyrim ещё нужно создавать адаптером.

## Повторные запросы и восстановление

Ключ повтора: `(actor, requestId)`. Пространства `system` и `player:<id>` разделены.
Повтор с другим содержимым отклоняется. Успешные ответы хранятся в той же транзакции, что и изменения.
Неуспешные команды не сохраняют квитанцию и могут быть повторены после изменения условий.
Все записи выполняются через `BEGIN IMMEDIATE`, SQLite WAL и `synchronous=FULL`.
Используйте один локальный файл базы на машине сервера; сетевые файловые системы не поддерживаются этой конфигурацией.

Квитанция описывает исторический результат команды. Она НЕ заменяет текущее состояние мира.
При повторе старого pickup после экстракции нельзя повторно вызвать Skyrim `AddItem`.
При подключении адаптер должен сверять игровой инвентарь с `snapshot(playerId)` и приводить его к актуальному состоянию.
Надёжная доставка событий в игровой процесс, блокировка игровых действий во время восстановления и обработка сбоя между коммитом базы и обновлением клиента ещё требуют реализации.

Отключение игрока не экстрагирует его и не завершает рейд. После подключения он остаётся в том же рейде.
Таймер отключения, присутствие персонажа в мире и защита от выхода во время боя относятся к будущему адаптеру.
Если доверенная система закрыла рейд, оставшийся инвентарь теряется.
Повторный вход в тот же рейд после смерти или экстракции запрещён; новый рейд доступен.

## Что подтверждают тесты

Проверяются идентичность предметов, потеря при смерти, чужой/повторный лут, атомарность ошибочного входа,
повторы команд, запрет второго активного рейда, изоляция рейдов, восстановление после открытия базы,
откат при искусственно вызванной ошибке записи и гонка двух независимых подключений за один предмет.
Это не проверка работоспособности Skyrim Together/SkyMP, качества PvP или защиты от игровых читов.
