# Общий контур боя и экономики — 0.9

Это реализация серверных правил и их проверки без Skyrim. Для подключения игры
нужен настоящий `RaidEnginePort`; готового игрового порта пока нет. Физика,
анимации, нанесение урона движком и два клиента остаются критериями C04/G1.

## Что закрыто без игры

| Блок | Реализация и проверка |
| --- | --- |
| Единое согласование | `RaidCoordinator`: freeze → одна SQL-транзакция → общий снимок → readback → ack → resume. Отказ оставляет мир замороженным. |
| Расходники | Списание UUID/количества и изменение HP/выносливости/магии/сопротивления в одной транзакции. Повтор возвращает прежнюю квитанцию. |
| Снаряжение | Оружие, щит, броня и вес определяются по фактическим UUID в инвентаре экспедиции. Подмена шаблона или чужой UUID отклоняется. |
| Смерти и задания | Смерть игрока одновременно создаёт контейнер и отчёт. Смерть NPC автоматически даёт предварительный зачёт убийце по серверной привязке цели; выход подтверждает прогресс. |
| Экстракция | HP, подключение, действие и счётчик повреждений берутся из боя; координаты/время — из доверенного порта. Урон сбрасывает удержание, недавний бой запрещает выход на 120 тиков. |
| Аварии и транспорт | SIGKILL до/после коммита лечения и смерти; HTTP с потерянным ответом, задержкой, перестановкой команд и повтором; потеря lease в ожидании readback. |
| Backup/doctor | Одна копия SQLite включает экономику, бой и все квитанции. Restore меняет databaseId, закрывает подключения, аннулирует lease. Doctor проверяет согласованность без вывода данных игроков. |
| Полигон и нагрузка | `/combat`: HUD, действия, смена оружия, расходники, журнал, сбой и восстановление. `qa:raid` нагружает 4 игроков + 28 NPC с двумя дисковыми SQLite: источник и имитатор проекции. |

## Хранение и совместимость

Схема 8 добавляет `raid_combat` и `raid_receipts` в основную базу. Последний боевой
снимок, связь actor↔экспедиция, счётчик повреждений, HP, эффекты, расход предметов,
смерть и квитанция фиксируются одной транзакцией. Промежуточные снимки тиков не
накапливаются в журнале квитанций; принятые команды имеют устойчивые requestId.

Поддерживается один открытый интегрированный мир на базу, до 4 игроков и 32 акторов.
Это явный предел этой версии, не обещание масштабирования на несколько миров.
Экономика сама по себе сохраняет прежнюю модель нескольких миров. Сохранённый
боевой снимок содержит версию 3 и rulesHash; изменение правил требует сверки
совместимости. Снимки с другим набором правил нельзя молча продолжать.

Миграции 0–7→8 сохраняют прежние UUID, остатки рынка и квитанции, добавляют новые
товары и один раз обновляют ревизию проекции. В каталоге 65 шаблонов, включая щит,
две брони, стрелы и посох. 103 физические привязки в шаблоне остаются пустыми:
FormID/позиции без проверки игровых файлов не подставлялись.

Старые `CombatJournal`/`CombatDelivery` и отдельный `ProjectionBridge` сохранены
как прежние компоненты с тестами. Их композиция **не является общим барьером**:
экономический мост может вызвать resume до подтверждения боя. Для новой
интеграции используется `dist/raid-runtime.cjs`. Смешивать два владельца resume
для одного мира нельзя. Автоматического импорта старого отдельного боевого журнала
нет: сначала завершите его недоставленные операции и закройте старый мир прежней
версией при замороженном движке, затем сделайте backup и обновитесь.

## Подключение доверенного адаптера

1. Открыть `ExtractionCore`, создать мир/экспедиции и связать реальные UUID экипировки
   через `RaidService.create`. Повторное создание уже существующего мира запрещено.
2. Создать `AdapterGateway`, получить lease по `ADAPTER_MANIFEST`, создать один
   `RaidCoordinator(service, gateway, lease, worldId, port, extractionPolicy)`.
3. Реализовать порт: проверенные transport→connectionId; freeze; абсолютную замену
   экономики и боя с readback; resume с проверкой epoch/снимка/срока lease;
   наблюдение столкновений и, при использовании, наблюдение выхода/проверку подбора.
4. Вызвать `start()`. Порт должен заморозить движок при старте процесса и при
   истечении lease самостоятельно: если сервер умер, его heartbeat уже не выполнится.
   `heartbeat(epoch, expiresAt)` обновляет сторожевой таймер порта. Вызывать heartbeat
   координатора каждые 5 секунд; срок аренды 15 секунд. Часы движка и сервиса должны
   согласованно трактовать переданный абсолютный срок либо использовать консервативный TTL.
5. Клиент передаёт только намерение; сервер вызывает `execute(verifiedTransportId, envelope)`.
   Другие пути изменения активного инвентаря (`consume/death/extract/pickup/close/recover/join`)
   защищены `RAID_COORDINATOR_REQUIRED`. Сам `RaidService` — доверенный внутренний API,
   не обработчик произвольных клиентских пакетов.
6. `advance`, `npc`, `contact`, `spawn`, `retire`, `connection` вызываются сервером.
   Контакт получает геометрию из порта, не из сетевого пакета. NPC удаляется только
   после смерти, ID остаётся в tombstone. Повторный вход игрока создаёт новую экспедицию.

`replaceAndVerify` возвращает `true` только после сверки обеих частей. Нельзя
превращать checkpoint в повторные DamageActorValue/AddItem: применяются абсолютные
значения. Порт должен учитывать epoch и ревизию также внутри асинхронного resume.
Полный серверный снимок содержит приватные схроны: реальным клиентам передаются
только разрешённые им поля и видимый мир.

`createCoreServer(core, token, {raid: coordinator})` включает закрытые маршруты
`/v1/raid` и `/v1/raid/{intent,advance,contact,npc,spawn,retire,connection,retry,recover,heartbeat}`.
`RaidClient` — клиент доверенного адаптера; ключ не выдаётся игроку. API сохраняет
лимиты размера, частоты, параллелизма и запрет browser Origin. При добавлении
координатора используется его gateway; новая аренда незаметно не создаётся.
Обычный `npm start` запускает экономическое ядро; настоящий порт в него не подставлен.

Конверт намерения: `{requestId, operation, payload}`. Для `input` payload содержит
только `{version, rulesHash, sequence, intent}`; остальные операции — `use {itemId}`,
`equip {weaponId, shieldId?, armorId?}`, `pickup {containerId,itemId}`,
`extract {exitId}`, `join {itemIds,loadout}`. Идентичный повтор сохраняет requestId
и payload. Игрок, урон, позиция, стоимость и время клиентом не задаются.

## Правила новых эффектов

- Лечение: 40 HP, сильное зелье 75 HP; предел 100. Зелья сил/магии: 45 единиц,
  предел 100. Все 12 расходуемых шаблонов каталога имеют явные эффекты в `raid-rules.mjs`.
- Применение требует живого подключённого бездействующего персонажа и занимает
  18 тиков восстановления. Бесполезное лечение полного ресурса отклоняется без списания.
- Лёгкая броня снижает физический урон на 15%, железная — на 30%, с округлением вверх.
  Вес всего переносимого имущества определяет категорию: меньше 20 / меньше 40 / 40+.
- Лук тратит одну настоящую стрелу при принятии атаки, даже при промахе. Повтор
  того же намерения не расходует ещё одну. Дистанция модели до 30 метров.
- Посох пламени — ограниченный профиль огненной атаки, а не вся магия Skyrim:
  30/45 магии, дистанция до 20 метров, серверное окно попадания. Реальные летящие
  снаряды и компенсация задержек не реализованы этой моделью.
- Сопротивление огню/холоду: 40% на 600 тиков; один слот эффекта, новый заменяет
  старый. Холод не защищает от огня. Источник холодного урона в этой версии отсутствует.
- Щит запрещён с луком/посохом; дальние атаки не парируются. Их можно блокировать
  или избежать перекатом по общим правилам. Это собственный исходный баланс.

## Восстановление

При неопределённом результате сначала `retry()` для общего readback. До него
новые команды отклоняются. Затем можно повторить исходный запрос без новых эффектов.
Даже корректный доменный отказ оставляет мир замороженным до явного retry: серверный
обработчик должен сверить состояние перед продолжением; полигон показывает эту кнопку.

После падения получить новую аренду, удерживать движок замороженным и вызвать
`recover(requestId)`. Операция допускается при неподтверждённом checkpoint:
смерть/расход уже зафиксированы в той же базе. Она возвращает только уцелевшие
исходные UUID снаряжения, уничтожает оставшийся рейдовый лут, не выдаёт награды,
закрывает обе модели и **не вызывает resume**. Продолжение сохранённого боя через
start технически поддерживается, но допустимо лишь при доказанной реконструкции
движка; до G1 используйте политику закрытия.

`npm run backup`, `npm run restore`, `npm run doctor` работают с одной базой.
Doctor выводит числа открытых/неподтверждённых миров, квитанций и коды нарушения
согласованности. Наличие pending — повод сверить состояние, а не повреждение базы.
Ошибочные связи бой↔экспедиция приводят к ненулевому коду завершения диагностики.

## Проверка и ограничения

`npm run qa:raid -- 600` выполняет 600 тиков, 4 игроков и 28 NPC с записью каждого
изменения в SQLite FULL и отдельным дисковым readback. Геометрия контактов в нагрузке
намеренно закрыта препятствием, чтобы сохранять постоянные 32 актора. Урон/смерти
проверяются отдельно в интеграционных и аварийных тестах. Измерение одного вызова
не означает соблюдения бюджета целого кадра при одновременных действиях всех NPC.
Игровые FPS, WAN, многосуточный soak и честность настоящего клиента не измерялись.

`npm run demo:ui`, затем `/combat` на выведенном локальном адресе. Полигон хранит
настоящие транзакции во временной базе; позиции, персонажи и столкновения условные.
Кнопка сбоя теряет подтверждение после записи, а восстановление сверяет обе части.
Для новой демонстрации после закрытия рейда перезапустите demo. Скриншоты и E2E
проверяют Chromium, не Skyrim CEF.
