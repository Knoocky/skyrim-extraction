# Решения и границы, обновлено 2026-10-05

## Цель

Extraction PvPvE в Skyrim. Первая игровая проверка: два игрока, один регион, один общий предмет,
смерть, подбор имущества погибшего и экстракция. Долгосрочно: большие экспедиции, убежище,
торговцы и динамический мир. Текущая версия проверяет только независимые правила владения предметами.

## Принято в прототипе

- JavaScript / Node.js 24, без сборки и внешних пакетов. Код можно выполнять и тестировать без Skyrim.
- SQLite хранит схрон и активный рейд. Игровой save не является источником прав на предметы.
- Каждый экземпляр снаряжения или стек имеет UUID; его нельзя одновременно держать в двух местах. У стека зелий есть количество.
- Команды и результаты выполняются/сохраняются атомарно. Повторы не повторяют мутацию.
- Мир должен авторитетно подтверждать подбор и экстракцию. В отсутствие адаптера операции запрещены.
- Смерть — доверенное событие. Подтверждение смерти и валидация боя не входят в этот модуль.
- Перезапуск не возвращает выданное снаряжение. Закрытие рейда уничтожает невынесенные предметы.
- В прототипе нельзя повторно войти в тот же рейд после терминального исхода.
- Нет публичного API, регистрации аккаунтов, модификации игры, подключения к STR/SkyMP или игрового контента.

## Принято для дальнейшей разработки

- SkyMP + SkyrimPlatform, TypeScript, React/CEF; целевой клиент Skyrim SE Steam 1.6.1170 на Windows 11 x64.
- Постоянное ядро — отдельный процесс Node.js 24 + SQLite; перенос текущего JS в TypeScript постепенно.
- Сервер Linux x86-64, Docker Compose. Адаптер SkyMP обращается к ядру по закрытому версионированному HTTP/JSON API.
- Решение, границы доверия и исходный снимок: [STACK.md](STACK.md). Стек выбран; игровая пригодность ещё не подтверждена.
- Бюджет: [план разработки](DEVELOPMENT_PLAN.md), активные агенто-часы с отдельным резервом; календарная дата релиза не назначена.

## Открыто до интеграционного эксперимента

- Воспроизводимая сборка выбранного снимка SkyMP, полный манифест зависимостей и условия их распространения.
- Подтверждение целевой версии Skyrim на двух клиентах; конкретные точки серверных перехватов.
- Схемы и реализация выбранного межпроцессного протокола: аутентификация сервисов, доставка и порядок событий.
- Соответствие UUID предмета сочетанию plugin + FormID + instance properties. FormID не уникален для экземпляра.
- Базовые стеки зелий и экономический расход реализованы в 0.2. Открыты: боеприпасы, свойства экземпляров, крафт/улучшение, сброс и применение расхода в игре.
- Согласование игрового состояния и базы при сбое. Требуются сверка версий и идемпотентная проекция.
- Порядок конкурирующих событий смерти/экстракции в игровом сервере. Сейчас победит первая принятая транзакция.
- Авторитетность позиций, боевого урона и смерти; одного реестра предметов для честного PvP недостаточно.
- Жизненный цикл тела отключившегося игрока, таймауты, очистка истории/квитанций.
- Политика опыта/навыков после смерти. Текущий код не ведёт прогрессию персонажа.
- Восстановление самих NPC и мира после перезапуска: ядро хранит только экономическое состояние.

## Критерий перехода к игровому MVP

На двух настоящих клиентах один предмет одновременно доступен двум игрокам, но достаётся только одному.
После смерти предмет доступен другому игроку. Экстракция сохраняет его один раз.
Переподключение и перезапуск восстанавливают согласованные инвентари без повторной выдачи.
Эти условия необходимо проверить в выбранном сетевом движке; unit-тесты ядра их не заменяют.
