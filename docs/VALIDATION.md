# Проверка версии 0.2

Дата: 2026-10-05. Локально: Linux, Node.js 24.19.0.

`npm test`: 25 тестов, 25 пройдено, 0 ошибок/пропусков. `npm run demo`: код завершения 0.

Новые проверки:

- Остаток стека после расхода сохраняется через смерть, чужой подбор и экстракцию.
- Повторы split/merge/consume не повторяют изменение, включая удалённый источник или последний предмет.
- Чужое владение, расход экипировки, неверные количества, переполнение и отсутствие разрешения отклоняются.
- SQLite-ошибка между уменьшением исходного стека и созданием нового откатывает весь split вместе с квитанцией.
- Два независимых подключения конкурируют за последнюю единицу: ровно одно списывает предмет.
- Миграция реальной схемы 0.1 сохраняет UUID/квитанции; повторное открытие безопасно; будущая схема отклоняется без оставленного блокирования.
- Отдельный дочерний процесс принудительно завершается до коммита: расход и квитанция отсутствуют после восстановления.
- Тот же процесс завершается после коммита до выдачи ответа: расход и квитанция сохранены; повтор не списывает второй раз.

Kill-тесты используют настоящий отдельный процесс и `SIGKILL` (на Windows Node применяет принудительное завершение процесса). Это не имитация отключения питания/сбоя диска. Целостность SQLite проверяется после восстановления.

[GitHub Actions для a74dfca](https://github.com/Knoocky/skyrim-extraction/actions/runs/37306044208): обе задачи `ubuntu-latest` и `windows-latest` завершены успешно; `npm test` и `npm run demo` прошли на обеих системах.
Игра, SkyMP, лечение, сетевой транспорт и устойчивое применение экономического состояния в Skyrim пока не проверены.

## История: версия 0.1

Дата: 2026-10-02.
Среда: Linux, Node.js 24.19.0, встроенная SQLite 3.53.3.

`npm test`: 14 тестов, 14 пройдено, 0 ошибок, 0 пропусков.
`npm run demo`: код завершения 0; сценарий двух участников со смертью, лутом,
экстракцией, повтором запроса и повторным открытием базы завершён.

Гонка выполнялась в двух worker threads с отдельными подключениями к одному файлу SQLite.
Ровно один участник получил предмет; второй получил `ITEM_UNAVAILABLE`.
Тест отката использовал SQLite trigger с искусственной ошибкой после переноса предметов.
Состояние инвентаря откатилось; повтор операции после удаления trigger прошёл.

Первый прогон выявил различие прототипов JS-объектов между прямым ответом SQLite
и повторным JSON-ответом. Возвращаемые строки нормализованы в обычные объекты;
полный последующий прогон прошёл.

Не проверено: Windows, настоящий Skyrim, STR/SkyMP, игровой сетевой транспорт,
авторитетность урона/позиций, сетевые разрывы настоящего клиента, принудительное
завершение процесса/отключение питания, нагрузка, надёжность проекции базы в игровой инвентарь.
Повторное открытие базы проверено после штатного закрытия соединения.
