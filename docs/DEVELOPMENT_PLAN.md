# Skyrim Extraction: план разработки до версии 1.0

Обновлено: 2026-10-05. Прототип: b6b9fd7; предыдущий план: 9338da3.
Статус: рабочий план. Выбран стек SkyMP/SkyrimPlatform, оценка переведена в активные агенто-часы.
Числа контента и баланса ниже — предлагаемый объём релиза, а не уже реализованные возможности.

## 1. Конечный результат

Версия 1.0 — устанавливаемый мод Skyrim с отдельным сервером, в котором можно самостоятельно начать персонажа, подготовиться в убежище, выйти в опасный регион, исследовать подземелья, сражаться с NPC и другими игроками, потерять снаряжение при смерти либо вынести добычу, развивать убежище и пройти завершённую цепочку прогрессии.

Одиночная игра использует тот же серверный режим с одним участником. PvPvE для 2–4 игроков входит в 1.0. Отключение PvP разрешено настройкой сервера; это не заменяет проверку PvP перед релизом. Начальный поддерживаемый формат — собственные серверы небольших групп. Автоматический матчмейкинг и общая экономика между чужими серверами не входят в релиз.

Игра сохраняет физическое путешествие по постоянной географии. Переход между наружным миром и интерьером сам по себе не заканчивает экспедицию. Общий мир и разные личные экспедиции сосуществуют: возвращение одного игрока не сбрасывает подземелье для остальных.

Это конечный объём первой полноценной версии. Вся карта Skyrim, Солстхейм, Чёрный Предел, большая симуляция конкурирующих искателей приключений, лошади, сложные травмы и 8+ участников — последующие расширения. Их нельзя незаметно включать в обязательства 1.0. Если целью объявляется весь Skyrim уже в 1.0, объём и сроки необходимо пересчитать до производства контента.

## 2. Текущее состояние

Готово независимое ядро 0.6: экономика предметов, сессии, outbox, HTTP, backup, кошелёк/торговля с конечным запасом, крафт, аварийный комплект, начальные контракты и шесть модулей убежища. Есть React UI с браузерной проверкой повтора покупки, правила удержания в зоне выхода, контейнер ядра с проверкой рестарта и экспериментальный SkyMP-порт. SkyMP сервер и native unit target с патчем успешно скомпилированы в CI без игровых данных. G1 ещё не проведён. Полный игровой контент и эффекты не готовы; актуальные результаты — в [PROGRESS.md](PROGRESS.md).

Пока не завершены игровой адаптер и клиентский сетевой протокол нашего мода; отсутствуют интерфейс в игре, аутентификация, привязка экземпляров предметов к Skyrim, боевое подтверждение, игровой контент и релизные сборки. Проверены штатное повторное открытие базы и два принудительных завершения процесса расхода до/после коммита. Отключение питания и полный набор сбоев пока не проверены. Тесты гонки используют два подключения SQLite, не два игровых клиента.

Прототип сохраняет полезные правила, но его внутренний API и схема будут развиваться. Принято [решение о стеке](STACK.md): SkyMP/SkyrimPlatform, TypeScript для наших адаптеров и логики, React/CEF для UI, отдельное ядро Node.js 24 + SQLite. Наличие Node.js 24 в нашем прототипе не означает совместимости со встроенным runtime сетевого проекта; отдельный процесс устраняет эту зависимость.

## 3. Правила, которые нужно закрепить перед интеграцией

| Решение | Рабочее правило |
|---|---|
| Источник постоянного прогресса | Серверная база. Клиентский save не может восстановить потраченный или потерянный предмет. |
| Владение | Экземпляр снаряжения имеет одного владельца/место. Для стеков сохраняется количество с учётом выдачи, расхода и уничтожения. |
| Смерть | Снаряжение и добыча переходят в серверный контейнер. Уровень, подтверждённый опыт, схрон и убежище сохраняются. |
| Опыт и магия | Только разрешённые сервером изменения. Заклинания ограничены требованиями, ресурсами и набором эффектов; сохранённые навыки не должны обесценивать потерю снаряжения. |
| Контракт | Предмет нужно вынести и сдать. Убийство/разведка учитываются после подтверждённого события; награда выдаётся один раз по правилам контракта. |
| Выход | Проверка позиции, состояния и времени на сервере; пробный порог удержания 10 секунд. Урон, смерть или уход из зоны отменяют процесс. |
| Безопасная зона | Урон между игроками запрещён; нельзя снять риск одной границей зоны посреди боя. Возврат в схрон происходит только после подтверждённого завершения экспедиции. |
| Отключение | Не является эвакуацией. Пробная политика: персонаж остаётся уязвимым 120 секунд; повторный вход продолжает тот же рейд. Нужна проверка возможности на движке. |
| Авария всего сервера | Восстановить мир и экономику согласованно либо завершить затронутую сессию по заранее объявленной политике компенсации. Частично восстановленный мир не открывается игрокам. |
| Сохранения | Технические сохранения разрешены для работы клиента; загрузка старого save не откатывает серверный прогресс. |
| Пауза и время | В общем мире меню не дают одному участнику остановить бой или перемотать время для остальных. |
| Сброс локаций | Только когда область свободна от игроков и защищённых переходов. Уход одного участника не сбрасывает общую область. |
| Давление мира | День/ночь, опасности, припасы и масса лута. Жёсткий таймер смерти в рейде не обязателен. Закрытие сервера — отдельная операционная процедура. |
| Изоляция | Хаб/схрон персональны. Подземелья в одном серверном мире общие. Разные серверы не обмениваются персонажами и предметами. |

Точные значения времени, массы, цен и наград являются настройками. Их принимаем после игровых тестов, а не зашиваем как доказанный баланс.

## 4. Последовательность разработки

### Как считаем время

**Один агенто-час — 60 минут активной работы одного агента над проектом:** изучение исходников, проектирование, изменения, анализ тестов, диагностика и исправления. Короткие необходимые вызовы инструментов входят в рабочую сессию. Длительные прогоны без участия агента, ожидание установки игры, доступа или ответа тестеров записываются отдельно. Это не CPU-час, не число токенов и не календарный час круглосуточной фоновой разработки.

Оценка дана для одного агента. Если позднее будет согласована команда, часы всех агентов суммируются; параллельность сама по себе не уменьшает трудоёмкость. Автономная работа между активными сессиями здесь не подразумевается.

Ниже — новый расчёт по задачам для выбранного SkyMP, а не деление прежних человеко-недель на коэффициент скорости. Диапазоны включают реализацию, проверку результата, анализ игровых логов и обычные исправления. Быстрее всего ожидается работа с кодом ядра, схемами, тестами и UI; у сетевой интеграции и игровых дефектов неопределённость выше. Статистики нашего темпа на таких задачах пока нет: уверенность низкая, числа являются плановым бюджетом, а не измеренной производительностью или гарантией.

|---|---|---|---|---|

**Сумма: 220–420 активных агенто-часов. Резерв 40%: ещё 88–168 часов. Итого 308–588, округлённый бюджет — 310–590 часов до версии 1.0.** Резерв покрывает повторные итерации, ограниченные нативные исправления и непредвиденные дефекты; он не подтверждает пригодность SkyMP заранее. Прежняя оценка в месяцах заменена этим бюджетом.

| Контрольный результат | Накопленный бюджет от текущего прототипа |
|---|---|
| Первая полностью играбельная версия P0–P4 | 92–176 часов без резерва; около 130–250 с резервом 40% |
| Полная версия 1.0 P0–P9 | 220–420 часов без резерва; около 310–590 с резервом 40% |

Это оценка **моей части всей разработки**, при условии доступного игрового стенда, выполнения необходимых действий в игре/редакторе и получения результатов тестов. Ручная работа владельца стенда, игровые сессии тестеров и ожидание результатов не становятся агенто-часами. Минимальные два четырёхчасовых прогона P8, например, требуют восьми часов реального времени стенда; моя настройка и диагностика учитываются в P8. Пока Skyrim отсутствует и доступа к такому стенду нет, календарный срок окончательного выпуска определить нельзя.

Предположения бюджета: объём раздела 1 сохраняется; используются существующие модели/локации; нет собственного сетевого движка, нового большого набора анимаций/озвучки и крупной переделки боя. Работа в Creation Kit и проверка контента требуют доступного редактора и оператора/инструментов управления им. Если выясняется необходимость масштабного форка или смены сетевой архитектуры, оценку пересчитываем до производства остального контента.

После первых 8–12 активных часов фиксируем фактическое время и завершённые проверяемые результаты; пересчитываем ближайшие задачи по факту. После G1 обновляем P3/P6/P8 по найденным ограничениям, после игрового MVP — оставшийся контент и баланс. В журнале задач отдельно ведём активные минуты, ожидание, результат проверки и оставшийся диапазон. Задачи, завершённые до этой оценки, повторно не считаем.

Критический путь: P0 → P1 → P2/P3 → P4 → P5/P6 → P7 → P8 → P9. Подготовка UI и контентных таблиц может идти параллельно, но не заменяет прохождение сетевых критериев.

### P0. Подготовка проекта

- Ввести статусы задач: planned, in progress, blocked, verified. Завершать задачу только с артефактом проверки.
- Разделить доменную модель, хранение, сетевой контракт, игровой адаптер и данные контента. Сначала модули одного проекта, без обязательных микросервисов.
- CI для ядра на Windows и Linux с выбранной версией Node. Зафиксировать версии сторонних инструментов, когда они появятся.
- Документировать исходный модлист, поддерживаемые версии, правила профиля и запреты клиента.
- Проверить условия использования выбранного сетевого проекта и сторонних ресурсов до их включения. Не распространять файлы Bethesda вместе с модом.

Результаты: спецификация правил, архитектурное решение, воспроизводимый запуск и тестовый протокол P1.

### P1. Проверка выбранного SkyMP — обязательный рубеж G1

Собрать SkyMP из начального снимка, указанного в [STACK.md](STACK.md). Записать commit, runtime, зависимости клиента, способ серверных расширений и нужные изменения исходников. Начальная цель — Skyrim SE Steam 1.6.1170. Проверить, где действительно принимаются решения об уроне, инвентаре, позиции и смерти. Выбор стека уже сделан; здесь доказываем его пригодность.

Для прохождения G1 недостаточно наличия PvP-переключателя или TypeScript. Для extraction также необходимы управляемые NPC, интерьеры, общий лут и исключение конфликтующей выдачи вещей.

| Эксперимент на двух клиентах | Что доказываем |
|---|---|
| Меч, блок, лук, снаряд, лечение | Оба видят согласованный исход; нет двойного урона и бесконечного лечения из-за рассинхрона |
| NPC и смена управляющего клиента | Противник существует для обоих, сражается с обоими и не ломается после отключения прежнего хоста |
| Одновременное открытие сундука | Один экземпляр достаётся только одному участнику |
| Смерть и лут погибшего | Можно перехватить исход, исключить ванильное восстановление и создать наш контейнер |
| Переход наружный мир ↔ интерьер | Предметы, идентичность игрока и смерть не теряются на загрузочном экране |
| Разрыв связи, старое сохранение, повторный вход | Клиент не вносит старое имущество в экономику |
| Создание локального предмета/изменение количества | Система отклоняет неподтверждённое владение и исключает выгоду в бою |
| Сервер отклоняет подбор или выход | Отказ имеет силу внутри игры, а не только в нашей базе |
| Чужой ID и устаревшее событие | Клиент не управляет чужим персонажем и не повторяет событие прошлой сессии |
| Меню, время, погодные эффекты | Один игрок не останавливает остальных; условия риска согласованы |

Результат G1: таблица pass/fail с логами/видеозаписями, зафиксированная сборка SkyMP, перечень необходимых изменений и обновлённая оценка в агенто-часах. Если SkyMP не позволяет контролировать ключевые операции в рамках ограниченных исправлений, ставим разработку контента на паузу и отдельно оцениваем форк или пересмотр стека. PvP не объявляется готовым и не заменяется PvE без отдельного решения о смене цели.

### P2. Надёжное ядро и хранилище

- Разделить серверный world/session ID, персональную экспедицию и подключение клиента. Текущая модель raid слишком груба для общего региона с разными моментами выхода.
- Разделить постоянную личность персонажа и временный actor ID; добавить поколение подключения, чтобы старые сообщения не управляли новым подключением.
- Описать предмет: plugin + локальный FormID для шаблона, UUID для экземпляра, количество для стека, разрешённые свойства зачарования/улучшения/заряда.
- Ввести расход, разделение/объединение стеков, использование зелий, стрел и зарядов, крафт, продажу и уничтожение. Для каждой операции — один атомарный экономический результат.
- Добавить ревизии состояния, журнал операций, уникальные события, ограничения входных данных и инварианты на уровне базы.
- Добавить очередь применения изменений в игру: коммит базы и запись задания в одной транзакции; повторное применение определяется версией, а не слепым AddItem.
- Определить порядок смерти и экстракции по серверным событиям. Первая случайно пришедшая клиентская команда не должна решать исход.
- Реализовать миграции, проверенное резервное копирование/восстановление, обслуживание квитанций и ограничение размера журнала.
- Тесты: перестановка и повтор сообщений, конкурентный расход, kill процесса в точках операции, повреждённая/недоступная база, восстановление после коммита до ответа.

Нельзя обещать одну атомарную транзакцию одновременно в SQLite и в движке Skyrim. Задача решается сохраняемой очередью, версиями и сверкой. До завершения сверки игровые операции с имуществом блокируются.

### P3. Адаптер к игре и серверу

- Реализовать выбранное размещение ядра отдельным процессом: закрытый версионированный HTTP/JSON API, сервисная аутентификация, квитанции, очередь и сверка ревизий. Runtime SkyMP и Node.js 24 ядра изолированы.
- Аутентифицировать подключение и привязать его к персонажу. Проверять соответствие модлиста и сетевого протокола.
- Клиент отправляет намерение, например «взять предмет». Сервер определяет игрока, допустимость, расстояние, принадлежность к миру и результат.
- Перехватывать/закрывать обходные пути: ванильные сундуки, контейнеры NPC, pickpocket, barter, crafting, drop, консольные предметы, команды телепортации и загрузка save.
- Применять подтверждённый инвентарь, экипировку, ресурсы и статус персонажа; отделить экономическую истину от визуального обновления.
- Реализовать смерть, серверный контейнер, безопасное возвращение, выход и повторное подключение.
- Проверить смену cell/worldspace, загрузочные экраны, смену хоста NPC и отключение во время подбора/экстракции.
- Не полагаться на запрет консоли как на античит: тестировать влияние локальных изменений на бой и прогресс.

Рубеж G2: два клиента выполняют цепочку «схрон → экспедиция → предмет → смерть → чужой подбор → экстракция → повторный вход» без ручного исправления данных. Прерывания связи не создают второй экземпляр.

### P4. Первая полностью играбельная петля

- Небольшой хаб, стартовая экипировка, один данж, три выхода и ограниченный каталог лута.
- Простая внутриигровая выдача/выбор снаряжения и итог экспедиции. Это уже игровой интерфейс, даже если оформление временное.
- Одновременное присутствие 2–4 участников; NPC и разрешённый PvP.
- Отключён обычный fast travel; загрузка save не возвращает имущество.
- Баланс риска: дешёвый стартовый набор, ограниченный переносимый вес, понятная ценность добычи.
- Провести 20 завершённых экспедиций с разными исходами, собрать длительность, причины смерти, стоимость вынесенного/потерянного и субъективные отзывы.

Рубеж G3: без инструкций разработчика игрок понимает, чем рискует, зачем возвращаться и как снова выйти после поражения. Если петля неинтересна, исправляем её до производства десятков контрактов.

### P5. Убежище, экономика и прогресс

- Постоянные улучшения шести модулей; визуальное состояние и возможности хаба соответствуют серверному профилю.
- Три торговых специализации, закупочные/продажные цены, запас товаров и денежные расходы. Покупка/продажа не создают бесконечную прибыль циклом.
- Рецепты алхимии, еды, улучшений и исследования. Если вводится износ/ремонт, описать его отдельно: наличие кузницы в Skyrim не означает готовую механику ремонта.
- Опыт, навыки, репутация и разблокировки; прекращение client-side прокачки неподтверждёнными действиями. Бесконечная магия и неограниченный перманентный урон нарушают ценность добычи — балансируем вместе с экипировкой.
- Контракты доставки, добычи, разведки, босса и спасения; правила прогресса/награды для соло, группы и смерти.
- Один сценарий спасения специалиста: сетевой NPC/цель сопровождения, подтверждённый выход, однократная награда, отсутствие постоянной потери специалиста из-за сбоя.
- Восстановительный контракт/набор после разорения. Игрок не оказывается навсегда без возможности продолжать, но не может бесконечно продавать бесплатную выдачу.

Приёмка: новичок доходит до средней ступени без админских подарков; после серии смертей остаётся путь восстановления; прогресс переживает обновление и рестарт.

### P6. Мир, контент и боевой баланс

- Подготовить связный регион, границы и естественные маршруты возврата. Закрытые края объяснены и не позволяют обойти учёт экспедиции.
- Проверить каждое подземелье: навмеш, двери, ловушки, ключи, головоломки, выходы и зависимости от ванильных квестов. Bleak Falls Barrow — кандидат, а не заранее доказанная совместимая локация.
- География постоянна. Меняются разрешённые население, лут и события; чистка/переселение возможны только после освобождения области всеми участниками.
- Согласованные день/ночь и риск. Холод/голод допускаются только если дают полезное решение и одинаково рассчитываются для участников.
- Места появления защищены от немедленного убийства; выходы имеют несколько подходов и контрмеры против безальтернативного кемпинга.
- Зафиксировать разрешённые заклинания и крики. Отдельно проверить невидимость, контроль, замедление времени, призывы и ragdoll; неподдержанные эффекты не попадают в релизный набор.
- Отбалансировать три боевых набора, PvE-нагрузку для соло/группы, ценность разведки и возвращения. Уровень зоны преимущественно задан контентом.
- Завершить 20–30 контрактов, финальный маршрут и повторяемую игру после основной прогрессии.

Приёмка: все заявленные локации пройдены в одиночку и группой; нет обязательной двери/квеста, который может необратимо заблокировать персонажа.

### P7. Интерфейс и доставка

- Экраны: подключение/ошибка версии, схрон, выбранное снаряжение, журнал контрактов, улучшения, ход экстракции, смерть и итоги экспедиции.
- Видимые статусы загрузки/сверки; повтор клика не дублирует покупку, награду или выход. Ошибки предлагают действие восстановления.
- Клавиатура/мышь и базовое управление геймпадом; шрифты и окна читаемы на 1280×800. Это не обещание работоспособности под Proton.
- Русский текст; строки вынесены для локализации. Звуковые и визуальные сигналы объясняют риск без обязательного чтения логов.
- Проверка установленных версий, манифест файлов, понятный порядок запуска сервера и клиента.
- Пакеты содержат собственные файлы и разрешённые зависимости. Скрипты установки не перезаписывают произвольный профиль модов и не требуют распространения базовой игры.
- Миграция, откат серверной версии вместе с совместимой резервной копией, безопасное удаление и перечень несовместимых функций.

Приёмка: минимум три новых тестера устанавливают мод по документации без устных подсказок; один разворачивает собственный сервер.

### P8. Beta и кандидат в релиз

Здесь исправляем и проверяем, а не добавляем новые обязательные системы. Каждый найденный дефект имеет воспроизведение, серьёзность, состояние данных и конкретную версию клиента/сервера.

| Проверка | Предлагаемый порог приёмки |
|---|---|
| Экономика | Не менее 10 000 автоматизированных последовательностей с повторами/перестановками; ни одного нарушения уникальности или баланса количества |
| Реальные экспедиции | Не менее 100 завершённых циклов на 2–4 клиентах за несколько сессий; нет потери подтверждённого имущества/двойной награды |
| Долгая работа | Два четырёхчасовых прогона с четырьмя клиентами на фиксированной сборке без критического рассинхрона и падения сервера |
| Нестабильная сеть | RTT 50/100/150 мс и потери 0/1/3%: операции сходятся, выход/смерть однозначны; комфорт боя оценивается отдельно |
| Сбои | Разрыв клиента и жёсткий перезапуск процесса до/после каждого важного коммита; исход объясним и не создаёт добычу |
| Враждебный клиент | Поддельный player ID, неизвестный предмет, огромный стек, повтор старого события, телепорт к выходу и подозрительный урон не дают непроверенной экономической выгоды |
| Производительность | На зафиксированном в G1 стенде без графических модов p95 времени кадра хуже чистой связки не более чем на 20%; нет нарастающей очереди экономических операций |
| Установка/обновление | Чистая установка, переход с предыдущей beta, откат с резервной копией и повторное подключение пройдены |
| Серьёзность дефектов | 0 известных P0/P1; P2 с обходом перечислены в release notes |

P0: порча постоянных данных, массовый дюп, компрометация управления сервером. P1: воспроизводимый сбой основного цикла, невозможность продолжить, подтверждённый обход экономики/смерти. P2: локальная проблема с приемлемым обходом, не нарушающая владение и прогресс.

Порог производительности — начальная цель; после G1 фиксируются характеристики ПК, разрешение, версия игры и метод измерения. Прохождение конечного набора тестов не означает отсутствия всех возможных читов.

### P9. Выпуск 1.0 и поддержка

- Заморозить версии и модлист, собрать клиент/сервер с воспроизводимыми исходниками и контрольными суммами.
- Выпустить tag 1.0.0, changelog, известные ограничения, инструкцию, конфигурацию-пример и политику сохранения прогресса.
- Повторить установку из окончательных архивов; не подменять её запуском из рабочей папки разработчика.
- Проверить резервную копию и фактическое восстановление. Для штатного рестарта дать предупреждение и сохранить состояние; аварийная компенсация применяется только по серверным данным.
- Определить сбор обезличенной диагностики с согласия, срок хранения, приватный канал для сообщений о дюпах и порядок hotfix.
- После выпуска зарезервировать время на исправления. 1.0 означает завершённый заявленный объём, а не прекращение сопровождения.

Финальная демонстрация: новый игрок устанавливает мод, подключается, снаряжается, проходит несколько экспедиций, переживает смерть и переподключение, улучшает убежище, выполняет цепочку контрактов, завершает сложную экспедицию и сохраняет весь подтверждённый прогресс после обновления сервера.

## 5. Что можно делать без установленного Skyrim

| Доступно сейчас | Требует игры и стенда |
|---|---|
| P0, изучение исходников и сборки выбранного SkyMP | Завершение G1 и подтверждение пригодности выбранного стека |
| Правила, протоколы, модель предметов, тесты сбоев и инвариантов P2 | Перехваты действий, реальный бой, смерть и применение предметов |
| Таблицы контента, экономическая симуляция, макеты UI | Проверка UI внутри клиента, меню и геймпада |
| Сборка доступной серверной части, если для неё не нужны игровые ресурсы | Запуск компонентов, требующих ESM/BSA и других локальных ресурсов |
| Стенд имитации сети, миграции и документация | Интерьеры, NPC, навмеш, локации, производительность и игровые прогоны |

Для G1 нужны две законные установки совместимой версии игры и два независимых клиента; желательно два ПК/тестера. Цель — Skyrim SE Steam 1.6.1170; полный набор зависимостей фиксируем при сборке SkyMP. Дополнительный контент Anniversary Upgrade и крупный модпак не входят в начальный стенд.

Нельзя закрыть весь P1 только тестами Node.js. До появления игрового стенда продвигаем независимую часть, но не объявляем интеграционные рубежи завершёнными.

Ближайший пакет без игры: P0 (4–8 часов), исследование/сборочная подготовка P1 (6–12), ядро P2 (20–36), контракт/имитатор адаптера из P3 (8–16), макеты UI из P7 (6–12). Всего **44–84 активных часа без резерва**, или примерно 60–120 с общим резервом 40%. Это подмножество общего бюджета, не дополнительные часы. При отсутствии игровых данных сборочный результат фиксируется с перечнем пропущенных проверок. Проверки P2 на имитаторе остаются предварительными до интеграции с реальным адаптером.

## 7. Основания и ограничения источников

Проверено 2026-10-05. Документация проектов — заявление их разработчиков; работоспособность нашей комбинации ещё предстоит проверить.

- [STR: Features](https://github.com/tiltedphoques/gitbook-wiki/blob/main/general-information/features.md): PvP предусмотрен, но проект ориентирован на кооператив; есть ограничения при работе с выброшенными предметами и меню.
- [STR: FAQ](https://github.com/tiltedphoques/gitbook-wiki/blob/main/general-information/faq.md): совместимость сторонних модов не гарантируется; версию игры нужно выбирать по поддерживаемой сборке.
- [STR: исходники](https://github.com/tiltedphoques/TiltedEvolution): исходный проект для изучения клиента, сервера, сообщений и условий распространения.
- [SkyMP: исходники и документация](https://github.com/skyrim-multiplayer/skymp): выбранная основа с инструментами SkyrimPlatform/TypeScript; наличие API не доказывает достаточную авторитетность боя.
- [SkyMP: server scripting](https://github.com/skyrim-multiplayer/skymp/blob/main/docs/docs_serverside_scripting_reference.md): описаны свойства и события, включая события, формируемые клиентским кодом. Каждое критическое событие требует проверки доверия.

Архитектурное решение и ссылки на конкретный снимок находятся в [STACK.md](STACK.md). SkyMP выбран за доступные точки реализации собственного режима и UI; контроль экономики, смерти, NPC и восстановления всё равно должен пройти G1. Удобство TypeScript сокращает работу над кодом, но не доказывает готовность игрового поведения.
