# Экономика 0.7 / баланс 3 / схема 6

## Данные и доверие

Неизменяемый серверный каталог src/economy.mjs задаёт офферы, контракты и улучшения. Клиент передаёт только идентификатор предложения/контракта/предмета и количество. Цена, шаблон выдачи, опыт и награда не принимаются из запроса. UI показывает ту же версию каталога; решение всегда за сервером.

Новые операции протокола 1: buy(offerId, quantity), sell(itemId, quantity), upgrade(moduleId, expectedLevel), learnSkill(skillId, expectedRank), acceptContract(contractId), turnInContract(contractId, itemIds). Все требуют актуального connectionId, запрещены при активной экспедиции. Версия протокола прежняя: изменения аддитивны, старый сервер отклонит неизвестную операцию. Игровой адаптер дополнительно обязан подтвердить нахождение в убежище.

Все операции используют общий механизм атомарных квитанций и outbox. expectedLevel/expectedRank предотвращают случайную покупку следующего уровня новым запросом со старого экрана. При неизвестном исходе UI блокирует новые действия и повторяет тот же requestId. Подтверждённый отказ позволяет исправить действие; ошибка после коммита не считается отказом.

## Начальные правила

| Объект | Правило |
|---|---|
| Кошелёк | Начальное золото 0; сохраняется после смерти; предел 1 млрд |
| Торговля | 10 офферов, 3 роли; общий конечный запас; продажа дешевле покупки даже при максимальной скидке |
| Опыт | 10 за единицу впервые извлечённой мировой добычи; 100/100/150 за три контракта |
| Уровень | 1 + floor(xp / 100), без влияния на боевые характеристики |
| Переговоры | До 3 рангов; 1 очко за ранг; +5% золота новых контрактов за ранг |
| Мастерская | 3 уровня, цена 100/200/400; скидка 5% за уровень, округление цены вверх |
| Архив | 1 уровень за 100; открывает третий контракт |
| Контракты | Лекарю 3 зелья → серебряное кольцо → двемерская реликвия; однократная цепочка |

Условия и итоговая награда фиксируются при принятии контракта. Смена баланса не меняет уже принятое поручение. Сдача принимает только собственные подходящие предметы в схроне, отнимает точное количество, сохраняет остаток стека. Покупные предметы допустимы для начальных поручений; их конечность ограничивает прибыль. Повторяемые контракты и торговая репутация не реализованы.

Покупные и стартовые вещи не дают опыт экстракции. Маркер первого извлечения принадлежит предмету, а не игроку: смерть/чужой подбор после первого выхода не дают повторной награды. Split/merge доступны только в схроне, куда вещь попадает после отметки об извлечении. Миграция не присваивает происхождение старым предметам: они не дают новый опыт. Закрытие мира удаляет лут с его маркерами.

## Миграция и ограничения

Схема 2 → 3 добавляет progression, player_contracts и loot_provenance, сохраняет активные экспедиции, UUID, databaseId и квитанции, обновляет полную проекцию. Старым игрокам назначается нулевой кошелёк/опыт без ретроактивных наград. Копия до обновления обязательна для отката; новое ядро продолжает поддерживать миграции с 0/1.

Пока нет ограничений веса, материалов для строительства, опыта от боя и полных деревьев навыков. Баланс предназначен для проверки цикла без игры. Настройка доходности, PvP и длительности прогрессии требует игрового тестирования.

## Версия 0.5: O01–O04

Единый каталог src/catalog.mjs используется сервером/UI и генерирует SQL-ограничения. Материалы и еда могут храниться стеками, но расходовать можно только consumable. Масса пока описательная: лимиты веса ещё не действуют. FormID не назначены без проверки игры.

craft(recipeId,batches) выбирает собственные материалы в схроне, проверяет мастерскую и золото, списывает точные количества и создаёт новый UUID в одной транзакции с квитанцией/outbox. Для снаряжения разрешён один результат за запрос; для стеков — до 100 партий и не выше MAX_STACK. Крафтовая продукция не получает свежий маркер лута и не приносит повторный опыт выноса. Временные эффекты еды/зелий отсутствуют.

recoveryKit() доступен вне экспедиции при пустом схроне и невозможности купить самое дешёвое оружие с текущей скидкой. Меч привязан к playerId; unique/FK/trigger запрещают снять привязку и переместить его в чужой инвентарь/контейнер. Продажа и сдача запрещены, крафт исключает связанные вещи. Смерть уничтожает меч; нормальные вещи по-прежнему остаются в контейнере. Схрон/экипировка с одним мечом не позволяют получить второй. Повтор старой квитанции ничего не создаёт.

market_stock общий на весь сервер. buy атомарно уменьшает запас вместе с кошельком. Продажа уничтожает товар и не изменяет ассортимент. Системный restockMarket(requestId,cycle) заменяет остатки заданным запасом только для большего целочисленного цикла; старый цикл отклоняется, повтор квитанции не пополняет повторно. Это серверная команда, не UI и не клиентское право. Расписание относится к O09.

Схема 3 → 4 сохраняет кошелёк/навыки/контракты/экспедиции/UUID, добавляет привязку комплекта и рынок, обновляет каталог/проекцию. Старые вещи остаются обычными; условия уже принятых контрактов не пересчитываются. Все миграции с 0–3 поддержаны.

## Версия 0.6: O05, серверная модель шести модулей

| Модуль | Ступени / стоимость | Серверный эффект |
|---|---|---|
| Мастерская | 3: 100/200/400 | До 15% скидки покупки; открывает ковку/зелья на первой ступени |
| Архив | 1: 100 | Открывает третий начальный контракт |
| Схрон | 3: 100/200/400 | +50 мест за ступень |
| Алхимическая стойка | 2: 50/100 | -1 золото за партию зелья, минимум 0 |
| Кухня | 2: 30/60 | -1 золото за партию пайков, минимум 0 |
| Стол разведки | 3: 100/200/400 | +10% опыта за новые контракты за ступень |

Числа — начальный баланс; расширение ступеней/рецептов и привязки визуальных объектов относятся к O07/O08/G1. Условия принятого контракта, включая опыт, остаются прежними после улучшения стола разведки.

Вместимость измеряется строками предметов (экземпляр или стек), не массой. used включает схрон и активный инвентарь игрока. Покупка, разделение и подбор резервируют новые места; крафт сначала списывает материалы, затем проверяет место под выход с полным откатом при отказе. Экстракция перемещает уже учтённые строки. Смерть освобождает места. Улучшение/объединение стеков позволяют освободить запас; выбрасывание из инвентаря через новый клиентский API не добавлялось.

Схема 4 → 5 добавляет уровни новых модулей и capacity_floor. Для старого игрока floor=max(100,число имеющихся предметов в схроне/инвентаре), поэтому миграция ничего не удаляет и не блокирует возврат. Новые игроки начинают со 100 мест. Старые остатки рынка, кошелёк, навыки, контракты, UUID и квитанции сохраняются.

Новый движок событийных и повторяемых поручений описан в MISSIONS.md; старая начальная цепочка сохранена для совместимости.

## Расширение 0.8

60 шаблонов / 10 рецептов / 27 контрактов / 6 модулей / 3 навыка. Полный источник — catalog.mjs, extra-offers.mjs, economy.mjs и missions.mjs. Fieldcraft добавляет 1 XP за ранг к каждой единице впервые вынесенной добычи; scholarship добавляет 5% XP за ранг новым контрактам. Все три навыка расходуют общий запас очков. Условия ранее принятых заданий неизменны.

Неповторяемая миссия даёт 10 репутации, повторяемая — 1. При переходе со схемы 6 репутация завершённых миссий восстанавливается один раз. Для финального маяка нужны предыдущая цепочка и 90 репутации. Он открывает финальный рецепт и маршрут выхода. Новые рецепты дополнительно проверяют завершённые миссии. Валидатор проверяет ссылки/DAG и отсутствие прибыли от перепродажи покупок/крафта; повторяемые доставки также не окупают покупку всех материалов с максимальной скидкой.

Стоимость, массы и ночной множитель являются исходным балансом модели; боевые эффекты и доходность реальных забегов измеряются на G1+.
