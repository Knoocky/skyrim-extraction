# Протокол 1 / схема базы 4

## Доверие

HTTP API — внутренний канал доверенного SkyMP-адаптера. Все маршруты требуют `Authorization: Bearer <server-key>`; ключ — 32 случайных байта в hex. Origin отклоняется. POST требует application/json и тело не более 16 KiB. Это не пользовательская аутентификация. Обладатель ключа имеет системные полномочия.

Адаптер обязан брать идентичность из подтверждённого сервером входа, проверять позицию, владение и исход боя. `worldApproved: true` формирует только сам адаптер по данным мира; нельзя копировать его из клиентского сообщения. По умолчанию pickup/consume/extract/death запрещены.

## Маршруты

| Метод / путь | Назначение |
|---|---|
| GET /v1/health | Состояние сервиса |
| POST /v1/command | Выполнение команды |
| POST /v1/snapshot | Снимок игрока по connectionId |
| GET /v1/projection | Последнее полное серверное состояние |
| POST /v1/ack | Подтверждение databaseId и revision |

Форма команды: `{protocolVersion: 1, requestId, operation, payload, connectionId?, worldApproved?}`. Точные поля и ограничения — `src/protocol.ts`; неизвестные поля отклоняются.

Системные операции: registerPlayer, createWorld, openConnection, closeConnection, closeWorld, recordDeath, restockMarket. Операции подключённого игрока: beginExpedition, pickup, consume, extract, splitStack, mergeStacks, buy, sell, upgrade, learnSkill, acceptContract, turnInContract, craft, recoveryKit. Для них playerId выводится из connectionId, а не принимается из payload. Операции активной экспедиции требуют её expeditionId вместе с worldId.

## Идентичность и повторы

Мир существует независимо от персональной экспедиции. beginExpedition после смерти/выхода создаёт новый expeditionId; состояние других участников сохраняется. Старые события не могут завершить новую жизнь. Legacy joinRaid сохраняет прежний запрет повторного входа; HTTP использует beginExpedition.

openConnection выдаёт новый непрозрачный connectionId и поколение. Предыдущий токен сразу недействителен, включая повторы. closeConnection не экстрагирует игрока и не удаляет инвентарь. Присутствие отключившегося персонажа в игре реализуется отдельно.

Ключ квитанции — `(actor, requestId)`, с раздельными системным и персональными пространствами. Повтор обязан сохранять исходные параметры; изменённый запрос отклоняется. Успешный результат сохраняется вместе с экономикой и новой ревизией одной транзакцией BEGIN IMMEDIATE. Неуспешные команды квитанций не создают. Повтор старой успешной операции возвращает историю, а не новое право менять игровой мир.

## Проекция и сбои

Outbox хранит последний полный снимок, включая databaseId и монотонную revision. Изменение данных, квитанция и снимок атомарны. Промежуточные ревизии объединяются; последний снимок остаётся доступен даже после ack. Старое подтверждение не убирает новую ревизию, подтверждение будущей или чужой базы отклоняется. Протокол рассчитан на один логический адаптер-потребитель.

ProjectionBridge сериализует команды, замораживает взаимодействия, сверяет состояние до и после команды, подтверждает применённую ревизию и только затем снимает блокировку. При ошибке остаётся замороженным. Потеря ответа требует повтора того же requestId; потеря ack требует повторной сверки полного состояния. SimulatedProjector сохраняет применённое состояние в отдельной SQLite для проверок восстановления.

SkyMpInventoryPort заменяет инвентари целиком и читает их обратно. Все сопоставления разрешаются до первого изменения. Частично применённый снимок ремонтируется повторным применением. Смена databaseId требует явного операторского восстановления. Серверный readback не является подтверждением CEF/Skyrim-клиента. Заморозка всех способов взаимодействия должна быть реализована интегратором.

Полный снимок содержит схроны всех игроков и доступен только серверу. Игровой UI должен получать только собственный схрон и разрешённые контейнеры. Demo-host показывает контейнеры двух тестовых персонажей намеренно.

Очередь не гарантирует однократность временных эффектов: лечение, урон и награды требуют отдельного устойчивого механизма и игрового подтверждения. Они пока не реализованы.

С версии 0.5 projection и snapshot также содержат market: cycle и stock[{offerId,quantity}]. В предметах аварийного комплекта добавляется recovery:true; обычные предметы сохраняют прежнюю форму.
