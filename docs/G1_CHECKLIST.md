# G1 — проверка настоящего игрового стенда

Статус: НЕ ПРОВЕДЕНА. Автотесты ядра не закрывают ни один игровой результат ниже.

## Условия старта

Два Windows 11 x64 клиента с законной Steam Skyrim SE 1.6.1170, согласованные SkyMP/SkyrimPlatform и зависимости, Linux-сервер со сборкой закреплённого снимка и патчем. Зафиксировать SHA всех компонентов, версии runtime, хеши собственного мода и конфигурации без ключей, модлист. Игровые ESM/BSA предоставить локально; не коммитить.

Нужны реальные привязки FormID, подтверждённый серверный login, обработка намерений, серверные проверки дистанции/выхода/смерти, создание контейнеров и механизм заморозки. До этого библиотека adapters/skymp.ts сама не запускает сценарий.

## Сценарии и критерии

| Проверка | Критерий pass | Результат |
|---|---|---|
| Одновременный вход двух клиентов | Разные подтверждённые личности, общий мир, правильный собственный инвентарь | Не проверено |
| Общий предмет и гонка подбора | Ровно один владелец в БД и на обоих клиентах | Не проверено |
| PvP и NPC | Сервер подтверждает урон/смерть, клиентская подмена отклоняется | Не проверено |
| Смерть A, подбор B, выход B | Те же экземпляры один раз переносятся в схрон B | Не проверено |
| Запрет зелья / craft / drop / transfer | Запрещённое действие не влияет на имущество и бой | Не проверено |
| Повторная экспедиция A | Новый expeditionId; старое событие смерти не влияет на неё | Не проверено |
| Отключение и повторный вход | Старое подключение отклоняется, имущество сверяется; тело остаётся уязвимым по правилам | Не проверено |
| Падение ядра/адаптера до и после commit/ack | Операции блокируются, восстановление не дублирует и не теряет подтверждённые вещи | Не проверено |
| Старое сохранение и подмена предмета | Клиентское имущество не становится источником постоянной экономики | Не проверено |
| Интерьер и границы ячеек | Оба клиента согласованно видят акторов, контейнеры и исход действий | Не проверено |
| UI в CEF | Схрон и выход доступны с клавиатуры/геймпада, чужие данные не раскрываются | Не проверено |

Для каждого запуска записать setup, шаги, expected/actual, pass/fail, журнал с requestId/expeditionId/revision без секретов, видео двух клиентов и минимальное воспроизведение отказа. При провале экономических/боевых критериев релиз блокируется. После G1 продолжать P2–P7 по DEVELOPMENT_PLAN; расширять контент до прохождения основного игрового цикла преждевременно.
