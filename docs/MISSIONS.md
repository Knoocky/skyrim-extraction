# Событийные контракты 0.7 / схема 6

Это серверная модель контрактов для стенда без игры. Достоверность убийства, разведки, спасения, принадлежности к группе и близости участников пока не устанавливается этим модулем. Их должен подтвердить настоящий игровой адаптер.

## Модель

Новый каталог MISSIONS содержит 6 определений: повторяемая доставка трав; разведка; два убийства; спасение; финальная смешанная цель (победа + вынесенная реликвия); повторяемый дозор. Три старых контракта доставки продолжают работать без изменений. Полный объём 20–30 заданий относится к O08.

Каждое принятие создаёт отдельный instanceId, сохраняет версию, цели, награду с бонусами переговоров/разведки и серверный цикл. Неповторяемая миссия доступна один раз. Повторяемая — не более одного раза за цикл; одновременно нельзя иметь две активные копии одного определения. Смена цикла не отменяет старое поручение: его можно завершить, затем взять новое. В графе зависимостей запрещены циклы и неизвестные ссылки.

| Операция | Кто вызывает | Смысл |
|---|---|---|
| acceptMission(definitionId) | Игрок через актуальное подключение | Принять в убежище при выполненных зависимостях |
| claimMission(instanceId) | Игрок через актуальное подключение | Сдать доставку, завершить и получить фиксированную награду |
| recordMissionEvent(eventId,worldId,kind,target,recipients) | Только доверенный сервер, worldApproved=true | Подтвердить исследование/убийство/спасение для 1–4 участников |
| advanceMissionCycle(cycle) | Только доверенный сервер | Перейти к большему целочисленному циклу |

Событие содержит symbolic target, а не произвольное описание предмета или размер награды. recipients = [{playerId,expeditionId}]. Все экспедиции должны быть активны и относиться к этому миру; один невалидный участник отклоняет всё событие. Движок отдельно проверяет допустимость группового зачёта: один лишь список игроков в API не доказывает участие в бою.

## Прогресс и смерть

Исследование/победа/спасение сначала записываются как pending для конкретной экспедиции. Успешная экстракция подтверждает их в той же транзакции, что возвращает имущество. Смерть и закрытие мира удаляют pending. Ранее подтверждённый прогресс сохраняется. Поэтому переживший экспедицию участник группы получает зачёт, погибший — нет. Спасение означает только серверное событие и успешный выход; настоящий NPC/сопровождение и постоянные услуги специалиста относятся к игровой интеграции/O07.

События до принятия поручения не засчитываются задним числом. Идентичность события — (worldId,eventId), отдельно от requestId HTTP. Новый requestId со старым eventId возвращает прежний результат без нового прогресса; изменение содержимого старого события отклоняется. eventId обязан быть стабильным идентификатором серверного события, а не каждый раз новым UUID при доставке.

Доставка забирает точное количество подходящих обычных предметов из схрона; аварийный комплект исключён. Награда, списание и статус COMPLETED атомарны с квитанцией/outbox. Отказ при начислении или подтверждении выхода откатывает все изменения. Повтор claim с новым requestId не выдаёт награду ещё раз.

## Демонстрация

В UI можно принять поручение, войти в экспедицию и нажать «Имитировать событие задания». Эта кнопка существует только в demo-host: события берутся из тестового каталога, player/expedition выводятся сервером стенда. В обычном интерфейсе этой кнопки нет. Для подтверждения нужно имитировать выход и получить награду в убежище.

Прогресс выводится как подтверждённый и «до выхода». Денежная награда и опыт показаны отдельно. Внутренние target IDs не показываются вместо названий целей.

## Восстановление и границы

Pending, подтверждённые цели, события и циклы хранятся в SQLite и переживают перезапуск. Миграция схемы 5 сохраняет прежние профили, модули, вместимость, рынок и экспедиции; новые таблицы пусты, cycle=1. Не удалять журнал событий/квитанций без будущей политики O12 — это защита от повтора.

Планировщик циклов, настоящие группы/дистанция, NPC, сигналы движка, полноценная репутация и экономика специалиста ещё не реализованы. Никакие кнопки демонстрации не являются доказательством работоспособности этих механик в Skyrim.
